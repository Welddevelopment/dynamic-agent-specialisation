# Post-comparison model offline runner

Date: 2026-08-05

## Result

The missing model-execution boundary between a proved commercial comparison winner and the sealed Level 1.5 offline gate is now implemented.

The original commercial comparison budget cannot silently carry into lifecycle testing. After a paid comparison proves a genuinely different compiler challenger, the system creates a second zero-authority plan bound to:

- the active lifecycle handoff plan;
- the exact comparison result;
- the exact challenger bundle and candidate fingerprint;
- the exact sealed post-comparison gate and verifier;
- the candidate's model, per-task cost ceiling and turn ceiling; and
- a new pricing hash and exact offline-gate budget.

## Execution boundary

The sealed cases release only after global paid-call approval, a separate post-comparison approval phrase, the exact new plan hash, an exact spend ceiling, same-day pricing confirmation and an API key.

The role-specific commercial evaluator then runs only the exact challenger in the fresh disposable cases. Each result is converted into an integrity-checked Level 1.5 observation with the exact independent verifier receipt, candidate version, outcome, safety state, cost and latency.

One failed verification, unsafe attempt or incorrect side effect preserves a failure artifact and stops the gate. Passing every case produces `offline-gates-passed-awaiting-shadow`. It grants no shadow, canary, activation or customer-write authority.

Durable cost reservations, response caching and hash-chained evidence are separate from the original comparison campaign. A private progress artifact preserves completed offline observations. The current runner can safely replay a stopped disposable case through the response cache, but the offline result is not described as a customer traffic result.

## Evidence boundary

This makes the future empirical offline gate executable; it does not supply a model-backed challenger result. A fresh commercial comparison must first prove a different compiler winner. The exact winner must then pass this separately approved offline campaign and the existing zero-authority shadow, explicitly authorized canary, promotion and rollback gates. Customer and production evidence remain separate.

# Public-safe personal-site briefing: DAS and the broader vision

Date: 2026-08-05

## 1. One-sentence explanation

**Dynamic Agent Specialisation (DAS) takes a bounded business role, builds several complete specialist-agent configurations, tests them against independently checked outcomes, and recommends the strongest safe option only when the evidence justifies switching.**

## 2. Problem and genuinely distinctive direction

Companies can already assemble agents from models, prompts and tools, but making a dependable specialist still requires many linked choices: instructions, context, model, tools, memory, permissions, escalation rules, cost limits and a definition of success. DAS treats that whole configuration as the thing to design and compare. The candidate is not allowed to grade itself; a separate checker reads the resulting external system state. The system may keep the company's existing agent when no challenger proves a meaningful improvement. This joined, evidence-gated specialist-construction loop is the distinctive product hypothesis. Do not publicly claim that no competitor has similar components or that DAS is universally superior.

## 3. Current implementation stage

The accurate maturity label is **private bounded local technical prototype**, not production software or a deployed autonomous employee. The same compiler/evaluation core has been exercised across three structurally different fictional business roles: procurement, SaaS support and CRM/revenue operations. Local product surfaces include onboarding, candidate comparison, optional technical evidence views, controlled activation/rollback mechanics, a private console, customer-local runtime packaging and bounded fleet planning. A fresh model-backed local three-role fleet campaign has also completed, while a separate deeper commercial support comparison is currently incomplete and must not be presented as a result.

The newest local adapter work can import an explicitly selected safe subset of an OpenAPI description or a pinned customer-local MCP tool server. Several bounded systems can appear in one specialist without discarding context, permission or independent outcome checks. No real customer system has been activated.

## 4. Strongest evidence that is reasonable to show publicly

- One compiler/evaluation mechanism has been exercised across three different fictional roles rather than one tailored demo.
- A fresh local model-backed campaign completed three role assignments, each with independent external-state verification, zero observed unsafe attempts in those tasks, no missing role, and completion of the parent broad goal.
- The repository currently passes 266 automated local tests. For a less brittle website line, use **“more than 250 automated local checks”** and date it.

Recommended public wording: **“A private local prototype now constructs and compares complete specialist-agent configurations across three fictional business roles, checks outcomes through separate external-state verifiers, and can safely retain the existing agent when a challenger has not proved an improvement.”**

## 6. Relationship to Capability Factory

DAS and Capability Factory are **separate projects, repositories and evidence bases**. Capability Factory explores how an agent can recognize that an ability is missing, acquire the smallest safe capability, verify it and resume the original task. DAS explores how a company can automatically construct and select the best complete specialist for a role. They may become complementary layers in a later system, but neither currently depends on or proves the other. Do not describe DAS as a Capability Factory feature or combine their test counts, costs, dates or maturity claims.

## 7. Broader company/technical vision

The broader vision is infrastructure that lets a company give high-level goals while software helps determine which specialists are needed, constructs or improves those specialists, gives them only the right capabilities and authority, verifies real-world outcomes independently, and retains what has proved useful. Capability Factory addresses the missing-capability layer; DAS addresses specialist construction and selection; a future bounded fleet-control layer could allocate work, add or retire specialists and coordinate them under explicit human-set policy, budgets and permission. This is a future architecture, not one finished product today.

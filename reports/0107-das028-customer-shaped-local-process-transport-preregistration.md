# DAS-028 customer-shaped local-process transport — preregistration

Date: 2026-08-14  
Budget/network: $0; zero model calls; loopback only; no external network

## Primary question

Can the exact generated DAS-027 action and observer modules cross genuinely
separate customer-shaped localhost process boundaries, with real authenticated
request/response serialization and failure handling, while preserving the
unchanged DAS-023 qualification and every customer/activation gate?

## Frozen boundary

- Reuse the DAS-027 flat-primitive, one-write, exact-reconciliation subset
  unchanged. Do not add nested schemas, custom authentication, streaming,
  callbacks or arbitrary transforms.
- Use two new fictional source/role packages: one OpenAPI 3.x pair and one
  pinned-MCP pair.
- Start three distinct customer-local process roles per package:
  1. secret lease issuer/verifier;
  2. action server;
  3. independently authenticated read-only observer server.
- The secret process alone receives credential values. Other processes and the
  parent receive only aliases and short-lived opaque handles.
- Action and observer use different aliases, principals, server identities,
  process identities and network ports.
- Business writes persist to a disposable durable state file. The observer
  reads that state independently and never accepts the action response as
  proof.
- Transport protocol is explicitly `http://127.0.0.1` only. No TLS result is
  claimed. Redirects, host/DNS changes and undeclared ports or paths fail.

## Qualification protocol

For each fresh package:

1. reconstruct the exact reviewed DAS-024 → DAS-023 → DAS-025 → DAS-026 chain;
2. compile unchanged DAS-027 implementation bytes;
3. start separate secret/action/observer processes on dynamic loopback ports;
4. bind exact process/server/source/package identities;
5. run the unchanged DAS-023 ten canonical classifications over actual network
   requests;
6. for post-commit response loss, restart the action and observer servers,
   explicitly adopt only identity-valid replacements, attach to the same
   durable state, observe the committed write and never replay it;
7. seal unchanged local acceptance-only evidence and a signed DAS-020
   nonactivating bundle.

## Required network evidence

- exact OpenAPI method/path/query/header/body or pinned-MCP RPC
  server/version/tool/schema serialization;
- authentication success plus explicit 401 and 403 behavior;
- distinct process and port identities for action and observer;
- connection failure, malformed JSON, oversized response and timeout handling;
- server restart and explicit replacement adoption;
- observer unavailable, stale, incorrect, duplicate, collateral and unknown
  outcomes through the unchanged classifier;
- authority revoked after a prior plan decision but before network send causes
  zero requests and zero writes;
- post-commit socket loss causes fresh-process observation and one write only.

## Required attacks

1. non-loopback host or DNS substitution;
2. unreviewed port/process replacement;
3. path, method, MCP tool or schema redirect;
4. credential alias swap and credential-value leakage;
5. same-process or same-identity observer shortcut;
6. false TLS-secure/downgrade claim on the HTTP-local transport;
7. conflicting length/transfer headers, malformed JSON or oversized body;
8. timeout race with no later commit;
9. stable server-identity drift;
10. generated implementation mutation or cross-package evidence reuse;
11. pre-send authority revocation;
12. replay after post-commit response loss.

## Stop conditions

Stop without the stronger result if any credential value reaches durable
artifacts, an observer shares the action process/authentication path, a redirect
or unadopted replacement is followed, a timeout later commits, a lost response
replays, any canonical control fails, or customer execution/activation becomes
true.

## Success rule

Both fresh packages must run the exact generated bytes over separate
authenticated localhost processes and pass 10/10 unchanged controls. Each must
recover one post-commit response loss after real process replacement with one
write/no replay, reject every frozen attack, and enter a signed nonactivating
bundle. The full repository suite must remain green.

## Claim boundary

A pass supports local process-boundary evidence for two fictional packages in
the strict subset. It does not establish TLS, remote networking, a hostile OS
boundary, real provider connectivity, customer credentials/authority,
customer-environment acceptance, activation, deployment, production security
or reliability, arbitrary OpenAPI/MCP support, human setup time or demand.

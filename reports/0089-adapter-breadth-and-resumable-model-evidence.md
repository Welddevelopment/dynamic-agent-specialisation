# Adapter breadth and resumable model evidence

Date: 2026-08-05

## Outcome

Two separate problems were addressed without rewriting earlier evidence.

First, DAS now has high-leverage customer-system adapter paths rather than only the three hand-built fictional role worlds. An explicitly selected subset of a local OpenAPI 3.x description can become a bounded executable adapter. An explicitly selected subset of a pinned customer-local MCP `tools/list` response can now do the same. OpenAPI and MCP runtimes can be composed into one multi-system specialist tool host while preserving exact tool allowlists, context requirements, authority checks, idempotency, uncertain-write reconciliation and independent external-state visibility.

Second, paid model campaigns now distinguish a provider funding rejection from an ambiguous interrupted call. A verified uncharged funding rejection releases its reservation, records a resumable pause, and preserves every settled response in an integrity-checked cache. A campaign-progress receipt binds the exact budget, cache, evidence ledger and pause files. Resuming the exact frozen plan reuses cached answers rather than paying for them again.

## Adapter breadth implemented

### OpenAPI

- exact operation selection rather than whole-API exposure;
- local component schema, parameter and request-body references;
- bounded request validation, response size and timeout;
- header API keys, bearer, basic and customer-managed OAuth access tokens through customer-local references;
- explicit write authority and idempotency headers;
- independent read operation plus mappings/assertions for uncertain-write reconciliation;
- private one-command local package compilation;
- direct composition of several APIs into one specialist tool host; and
- a joined local test in which one specialist read a separate inventory API, created an order through another API, and passed independent combined external-state verification.

### MCP

- pinned `tools/list` response and exact selected subset;
- explicit read/write classification;
- bounded structured input and structured-result requirement;
- explicit context and authority requirements;
- mandatory caller-supplied idempotency field for writes;
- separate selected read tool plus mappings/assertions for uncertain-write reconciliation;
- no credential or transport configuration in the generated package;
- private one-command local package compilation; and
- the same multi-system composition boundary used by OpenAPI runtimes.

## Honest boundary

This materially reduces the integration-breadth weakness; it does not eliminate it. DAS does not yet have LangChain's or CrewAI's connector/community breadth, and no real customer API or MCP server has been activated. The importer cannot safely infer business authority, write semantics, reconciliation rules or the final goal-level verifier from documentation alone. Browser-only systems, arbitrary OAuth lifecycle management, binary/streaming APIs, webhooks, pagination orchestration, database drivers and unsupported custom protocols remain outside this checkpoint.

The prospective Level 2 result is fresh model-backed local fictional evidence, not customer evidence or production reliability. The commercial support comparison has no result until every frozen stage and repeatability run completes. Customer demand, setup time, real-world adapter compatibility and willingness to pay remain unvalidated.

# 0091 — Plain-English discovery safety repair and first paid smoke

## Verdict

The plain-English discovery safety boundary is repaired, the complete deterministic suite is green, and the first prospectively frozen model-backed frontend discovery smoke passed its independent structural and authority-safety benchmark.

This is a meaningful bounded result: one normal-language job description plus approved synthetic project material produced a useful provisional specialist contract without granting authority or pretending the execution environment was ready. It is not evidence of arbitrary-role onboarding, a complete self-serve product, specialist performance, customer value or production reliability.

## Deterministic repair

The initial full suite exposed twelve real failures. They came from four implementation seams rather than one unsafe policy:

1. strict input validation rejected optional fixture values that should have been omitted;
2. stale tests and the console still used pre-migration readiness and raw-import shapes;
3. customer confirmations were not bound to the exact prior fact identity and value;
4. the console-to-discovery join lacked a server-verified import receipt.

The repair preserved the fail-closed rules. Raw browser import proposals remain rejected. A receipt is minted only from an integrity-checked server-side onboarding record and binds the session, revision, record hash and proposal. Credential material remains rejected. Consequential confirmation binds the prior fact ID and hash. Exact unknown paths still fail closed.

Final deterministic verification:

- restricted full suite: **399 passed, 0 failed, 1 environment-skipped**;
- separately authorized localhost endpoint: **1 passed**;
- effective total: **400 passed, 0 failed**.

The count is a repository regression result, not a reliability percentage or customer outcome.

## Preserved failure chronology

The one model call settled successfully, but its first deterministic post-processing attempt failed: the provider-neutral product boundary still permitted only exact zero-call providers. No retry was made.

After adding an exact, plan-bound, instrumented usage authorization, replaying the persisted response exposed two further provenance seams:

- one artifact locator referred to the wrapper shown to the model rather than the stored artifact content;
- one approved current-agent source was labelled as an artifact.

Both now downgrade to unverified, review-required proposals. A truly unknown source still fails closed. The final pass came from the exact persisted response cache with **zero new calls and zero new spend**. The report explicitly separates the original campaign charge from the replay invocation.

## Exact evidence boundary

Supported now:

> In one frozen synthetic frontend case, DAS used a model-backed discovery provider to draft a provenance-labelled, execution-blocked role contract from a normal job description and approved project evidence. The contract passed the independent structural and authority-safety benchmark.

Not supported:

- arbitrary or universal role discovery;
- a normal user completing the whole onboarding journey without engineering;
- executable Figma, repository, Storybook or GitHub bindings;
- a comparison-ready or activated frontend specialist;
- generalization across the remaining six frozen cases;
- customer value, demand, production safety or reliability.

## Next decision

Do not automatically run the remaining six paid cases. First join frontend discovery to the real assisted-onboarding lifecycle, add replay-only evidence tooling, and seal a new multi-case plan. Then the next paid gate can answer whether the result generalizes beyond this one canonical contract rather than merely repeating it.

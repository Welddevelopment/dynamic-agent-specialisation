# Checkpoint 0100 preregistration — source-grounded package-draft authoring

Date frozen: 2026-08-14  
Work item: DAS-024 / zero-spend productization lane  
State: protocol frozen before opening the fresh authoring fixtures

## Primary question

Can one deterministic, integrity-bound authoring path turn a bounded ordinary-language business intake plus one exact pinned OpenAPI or MCP source into:

1. a source-grounded operation and schema inventory;
2. an explicitly provisional, non-executable DAS-023 package draft;
3. the minimum exact ordinary-language question graph needed to supply every consequential business, authority, write-safety and proof fact;
4. a restart-safe revision chain that rejects stale, contradictory, cross-role and cross-source answers; and
5. after every required fact is explicitly confirmed, the unchanged DAS-023 package and twenty-control paired qualification path?

This tests whether DAS can remove author-only translation and omission work without disguising consequential human decisions as inference. It does not test human usability or setup time.

## Frozen source families

The executed authoring campaign must use three unopened fictional fixtures:

- one OpenAPI 3.x source with at least one bounded write, one action-plane read candidate and one operation outside the role;
- one pinned MCP tools/list source with a materially different operation and idempotency shape, plus a separate pinned observer candidate source;
- one ambiguous or malicious source containing instruction-like descriptions, unsafe or unclear write semantics, and insufficient independent proof.

The complete fixtures, expected source-grounded inventory and required-question keys must be hashed before the first completed package enters DAS-023 qualification.

## Frozen input boundary

The authoring engine may receive only:

- a bounded ordinary-language role label and role outcome;
- the intended mutation and desired externally observable outcome;
- any known stable-identity fields, stated as customer proposals rather than proof;
- ordinary-language limits and escalation owner;
- one exact pinned OpenAPI document or MCP tools/list response with exact source identity;
- environment-reference credential aliases, never credential values; and
- later, explicit answers to exact generated questions.

It may not receive a pre-authored DAS-023 write-safety or observer-proof contract as hidden input.

## Frozen fact statuses

Every material fact must carry one of these statuses:

- `observed` — exact input supplied directly;
- `extracted` — exact schema/source material extracted without semantic invention;
- `inferred-proposal` — a non-authorizing candidate requiring confirmation;
- `owner-confirmed` — explicit business/authority/outcome answer;
- `engineer-confirmed` — explicit implementation/safety/runtime answer;
- `independently-verified` — evidence produced only by a separate later verification gate; or
- `unknown` — unresolved and blocking when consequential.

No source description, annotation, operation name or ordinary-language phrase can by itself become authority, write-safety meaning, observer independence, success proof, fault semantics, execution readiness or activation readiness.

## Frozen question families

The question graph must cover, without silent defaults:

- exact action operation and role mapping;
- exact read-only source operations and their purpose;
- stable business identity and assigned-work mapping;
- idempotency/conflict key and conflict behavior;
- allowed mutation kind, scope and maximum write count;
- action runtime, transport, schema and authentication identities;
- reconciliation/readback mapping and no-blind-retry rule;
- separate observer source, transport, implementation, authentication and credential alias;
- exact completed, not-started, partial, incorrect, duplicate, stale, collateral, unknown, unavailable and lost-response meanings;
- freshness fence and rejection of future or pre-existing evidence;
- authority, approvals, forbidden actions, escalation and unknown-state handling; and
- named owner/engineer review identities.

Questions may be dependency ordered. A lower-level question may remain blocked until its source operation or stable identity is confirmed. The engine must not omit a question merely because it can propose an answer.

## Frozen protocol

1. Normalize and hash the bounded business intake, pinned source material and aliases. Reject credential values and unbounded/unsupported source structures.
2. Treat all source descriptions and annotations as inert data. Extract only exact schemas, operation names, parameters, response/error shapes, authentication alias requirements and read/write candidates.
3. Create revision zero with provenance-labelled facts, an exact question graph, blockers and all protected gates false.
4. Apply answer batches only against an exact session, revision, role, source and question hash. Preserve an append-only hash chain.
5. Reject stale answers, unknown question ids, duplicate/conflicting answers, cross-role/source/package replay, credential values, widened authority, missing unknown/unavailable semantics, shared action/observer trust identity, and ungrounded source-operation claims.
6. Reload the durable state in a fresh process and recompute the exact same current receipt.
7. A complete answered draft may be translated into DAS-023 factory inputs only if every consequential fact is explicitly owner- or engineer-confirmed. It remains non-executable and unactivated.
8. Run completed OpenAPI and MCP drafts through the unchanged DAS-023 package factory and paired twenty-control qualification machinery. Keep authoring measurements separate from qualification evidence.
9. The ambiguous/malicious fixture must stop with exact blockers and must not enter DAS-023 qualification.

## Primary metric

Whether both fresh completed source families reach an integrity-valid non-executable DAS-023 package without a hand-authored package-definition bypass, while the ambiguous/malicious fixture stops before package generation.

## Secondary metrics

- extracted, proposed, owner-confirmed, engineer-confirmed, independently verified and unknown facts;
- total questions, blocking questions, answer revisions and explicit owner/engineer decisions;
- source operations considered, selected and rejected;
- prompt-like source strings preserved only as inert evidence;
- package-specific executable code and callbacks;
- author interventions after fixture freeze;
- stale/conflicting/cross-package answers rejected;
- fresh-process replay and receipt equality;
- DAS-023 controls, writes, observer writes, retries and lost-response replays, separately reported;
- executable operations, credentials, runtime authority, comparison readiness and activation status;
- model calls and spend.

## Frozen attacks

- source/prompt injection asking to grant authority, skip questions, mark proof verified or activate;
- write/read annotations or method names treated as authority or business meaning;
- credential value smuggling through aliases, URLs, descriptions, answers or nested source schemas;
- same action and observer source, transport, implementation, authentication, principal, surface or alias;
- action response or action-plane readback presented as independent business proof;
- unstable or incomplete identity and missing conflict behavior;
- blind retry, unsafe conflict overwrite or more than one allowed business write;
- stale source digest, source-schema drift and runtime-identity substitution;
- conflicting answers inside or across revisions;
- stale revision answer, cross-role answer, cross-source answer and cross-package replay;
- incomplete observer contract or omitted unknown/unavailable/freshness/collateral semantics;
- future or pre-existing evidence accepted as completion;
- any authoring receipt claiming executable, accepted, comparison-ready or active.

## Success criteria

- exact source-grounded inventory for both valid fixtures;
- every consequential fact explicitly confirmed rather than inferred;
- zero credential values and zero implicit authority grants;
- exact hash-linked revisions survive fresh-process reload and replay;
- every frozen attack fails closed;
- both complete drafts create integrity-valid DAS-023 packages and pass the unchanged paired twenty-control local machinery;
- ambiguous/malicious input remains blocked with no package or qualification result;
- package-specific executable code and callbacks remain zero;
- all protected readiness/activation gates remain false;
- zero model calls and zero spend.

## Kill and no-claim rules

The authoring result fails if a fixture embeds the final DAS-023 declaration as hidden input, any consequential fact is silently inferred, prompt-like source text changes policy, answer replay crosses an integrity boundary, the observer shares the action trust plane, a protected gate becomes true, or the ambiguous control reaches qualification.

Even a full pass is private deterministic local evidence. It cannot establish unassisted customer onboarding, human setup-time reduction, arbitrary OpenAPI/MCP support, real credentials/transports, production reliability, demand, comparison readiness or activation.

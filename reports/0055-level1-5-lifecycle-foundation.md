# Level 1.5 lifecycle foundation

Date: 2026-08-02

## Status

Substantial Level 1.5 control-plane foundation is implemented. Full bounded Level 1.5 is **not yet claimed**.

## Implemented

- Independent runtime outcomes can be converted directly into sealed, version-specific performance observations.
- Runs without an independent terminal verdict are excluded rather than treated as failures or successes.
- Performance windows distinguish ordinary drift from unsafe behavior.
- An unsafe active observation halts the specialist immediately.
- Ordinary drift creates a transparent optimization request only when optional optimization is enabled.
- The request is bound to the active registry record, quality floors, metrics, hard model budget, time, round, repeat, and stopping limits.
- Even an enabled request cannot run without explicit confirmation and a verified role-specific runner.
- A development winner cannot auto-promote. A challenger must pass disposable offline evidence, zero-authority shadow evidence, and a small explicitly authorized canary.
- Shadow evidence is mechanically rejected if any business write was committed. Canary evidence carries and enforces the authorized traffic fraction.
- Unsafe shadow or canary evidence quarantines the challenger.
- A promoted specialist can roll back to the prior proven version after independently monitored regression.
- Monitoring, requests, halt state, canary state, registry selections, alternatives, and lifecycle events persist across restart with integrity checks.
- The private console now has a read-only lifecycle view grounded in the Level 1 registry and this rehearsal.

## Three-role rehearsal

A zero-cost deterministic rehearsal exercised three distinct branches using the real saved Level 1 packages:

- procurement: healthy evidence continued the current specialist without search;
- support: drift created a `$1`-capped unstarted request, a preserved challenger passed offline/shadow/canary gates, promotion occurred, a simulated unsafe regression was detected, and the prior compiler specialist was restored;
- RevOps: one simulated unsafe active outcome halted the role immediately.

All six rehearsal checks passed. State was reloaded from disk and tampering tests passed. This is lifecycle-mechanics evidence only; observations were constructed fixtures, not fresh model or customer outcomes.

## Important repair made during this phase

The first implementation called a stage “shadow” but did not prove from the evidence record that no real business write had occurred. That label-only boundary was rejected. Observations now have enforced `disposable`, `shadow-no-authority`, `canary`, or `live` execution modes, and shadow records with any committed write fail closed.

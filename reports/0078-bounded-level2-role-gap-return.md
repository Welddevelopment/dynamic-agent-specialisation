# 0078 — Bounded Level 2 role-gap return

## Question

Can a broad company goal safely continue after the first fleet plan discovers that no proved specialist exists for part of the work—without silently granting authority, rerunning already verified work or pretending the parent goal is complete?

## Implemented chain

1. Reused the durable prior execution state in which 105 of 115 fictional items had been externally verified and the parent remained blocked on ten finance-close items.
2. Bound the finance gap to an exact system, tool, context, authority, policy and independent-verifier requirement.
3. Sent that requirement through the existing generic Level 1 compiler. Multiple deterministic candidates were compared; `finance-close:balanced` won with 100% frozen-case success and zero safety violations.
4. Registered and activated that exact winner under the finance policy, authority and verifier boundary. The role request itself granted no model-spend, creation, activation or customer-write authority.
5. Replanned the original broad goal with the added specialist. The new plan retained every prior assignment hash unchanged and eliminated the finance role gap.
6. Created a separate residual-only continuation. An accountable approval had to bind the exact continuation and residual assignment set.
7. Ran only the ten finance items through the disposable finance world. The existing independent external-state verifier observed five correct matches and five correct escalations, with no unrelated-state changes.
8. Carried the 105 prior verified items by immutable receipt rather than executing them again. The parent completed only after the residual observation passed and durable state survived reload.

## Result

- Prior verified items carried without rerun: **105**
- Newly executed finance items: **10**
- Finance residual success: **10/10**
- Finance safety violations: **0**
- Expanded coverage: **115/115**
- Remaining role gaps: **0**
- Final durable state: **`original-broad-goal-completed`**
- Full repository suite: **223/223 passing**

The continuation also fails closed if completed assignments change, if an added assignment is not part of the prior role gap, if activation does not identify the exact selected specialist, if prior external verification is incomplete, or if the residual controller is asked to rerun carried work.

## What this demonstrates

Within one bounded fictional environment, the complete deterministic control mechanism now exists:

> broad goal → proved-specialist allocation → safe partial completion → honest missing-role detection → separate specialist comparison and activation → residual-only replan → external verification → original-goal completion.

The important result is not merely that a finance candidate can complete ten cases. It is that the system can return from a missing-role boundary without losing the original goal, widening authority or duplicating already completed business actions.

## Evidence boundary

The finance specialist and its cases are deterministic local references. This is not a fresh model-backed specialist-generation result, a customer workflow, proof of arbitrary role discovery, proof that the system knows how a real company should be organized, production reliability, or commercial Level 2 validation. The existing empirical Level 1.5 gap also remains: a fresh drift-triggered model campaign and its exact winner must pass the joined offline, shadow, canary and rollback lifecycle under separate paid approval.

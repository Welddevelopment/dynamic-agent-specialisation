# DAS-027 declarative runtime compiler — preregistration

Date: 2026-08-14
Budget: $0; zero model calls and zero network access

## Primary question

Can DAS cross from a complete non-executable DAS-026 work pack to actual
disposable implementation bytes for a deliberately bounded declarative subset,
without inferring business meaning, credentials, authority, proof semantics, or
production readiness?

## Frozen supported subset

- One reviewed write operation per package.
- OpenAPI 3.x action/observer pairs with exact pinned HTTP method, route,
  parameter locations and a flat bounded JSON request body; or pinned MCP
  action/observer pairs with flat bounded object input schemas.
- Only primitive string, integer, number and boolean inputs, optional enum,
  pattern, minimum/maximum and minimum-length constraints, and
  `additionalProperties: false`.
- Exact owner-confirmed stable identity, allowed mutation, authority, outcome,
  duplicate/collateral and terminal behavior from DAS-024/DAS-023.
- Exact engineer-confirmed conflict key, reconciliation, independent observer,
  freshness, predicates/invariants and evidence timing.
- Customer-local opaque credential leases supplied only to the running test
  resolver. Generated files and durable evidence contain aliases only.
- An explicit engineer-reviewed execution profile adds a hard request ceiling,
  timeout, no-streaming/no-custom-transform/no-dynamic-operation rules. It is
  bound to the exact DAS-026 work-pack identity.
- No automatic retries. The generated runtime can reconcile; the unchanged
  qualification runner remains the only disposable control-loop authority.

## Explicitly unsupported

Custom authentication code, OAuth/account setup, signing schemes, streaming,
websockets, arbitrary code or transforms, callbacks, nested or ambiguous
schemas, external references, dynamic endpoints/tools, missing independent
observers, shared action/observer credentials, unconfirmed business semantics,
non-idempotent writes without a reviewed reconciliation operation, and any
source text that looks like an instruction.

Each unsupported feature must return a precise implementation/proof blocker.
Nothing may be silently approximated.

## Fresh experiment worlds

Use two new fictional packages that were not used by DAS-024, DAS-025 or
DAS-026:

1. one OpenAPI package;
2. one materially different pinned-MCP package.

Both must begin from fresh source, role and review chains, compile actual
separate action/observer project bytes, use customer-local test-only credential
resolvers, and enter the unchanged DAS-023 ten-control qualification path.

## Required evidence

- Exact proposal, work-pack, generated implementation and conformance
  identities remain distinct.
- Generated implementation file/line/function/operation counts.
- Explicit reviewed declarations versus generated code versus any handwritten
  package-specific implementation code.
- 10/10 canonical controls for each candidate, including fresh-process
  post-commit lost-response reconciliation.
- Zero observer writes, blind retries, replayed writes, secret leakage and
  surviving incorrect effects beyond the frozen control expectation.
- Each qualified fictional result must enter a separately signed DAS-020
  nonactivating bundle while activation and customer execution remain false.

## Required attacks

- bypass or move the authority hook after transport;
- insert a credential value or persist an opaque lease;
- widen endpoint, HTTP method, MCP tool, schema, fields, rate or timeout;
- accept the action response as proof;
- add observer write authority or collapse observer/action identity;
- perform a blind retry or replay a post-commit lost response;
- mutate generated bytes after their implementation identity is sealed;
- reuse implementation or conformance evidence across packages;
- omit an unsupported-feature or activation blocker from packaging.

## Success rule

Both fresh packages must compile actual separate runnable implementation bytes
without package-specific handwritten executable code. Both exact candidates
must pass 10/10 unchanged DAS-023 controls and produce valid signed DAS-020
nonactivating bundles. Any safety failure blocks the stronger result.

## Claim boundary

A pass supports only that DAS can compile and locally qualify exact disposable
implementation candidates for the frozen declarative OpenAPI/MCP subset. It
does not establish real provider connectivity, customer credentials, customer
authority, customer-environment acceptance, activation, production security or
reliability, arbitrary OpenAPI/MCP support, self-serve onboarding, demand, or
human setup time.

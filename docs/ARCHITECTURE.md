# Architecture

## Current bounded Level 1 architecture

```text
Messy company input
  -> six-part job brief
  -> prior knowledge + retained specialists
  -> complete candidate portfolio
  -> hard structural/authority rejection
  -> deterministic development diagnosis
  -> controlled child candidates
  -> staged tournament
  -> sealed unseen-case release
  -> independent external-state verification
  -> autonomous recommendation
  -> durable versioned registry + alternative preservation
  -> integrity verification + safe activation/switching
```

Candidate packages include model policy, instructions, context, tools, memory, authority, escalation, verifier binding, budgets, provenance, and version.

The provider-neutral runtime now supports bounded tool loops, tenant/role/version-isolated memory, authority checks before execution, external verification, lost-response reconciliation, and fail-closed unknown outcomes.

Structured model boundaries now exist for both complete candidate architecture and runtime tool decisions. The real Responses provider is disabled unless code-level authorization and the explicit `DAS_ENABLE_PAID_MODEL_CALLS=JOEL_APPROVED` flag are both present; current pricing must be injected rather than silently hard-coded.

Five compact role adapters remain deterministic architecture stress tests. Three richer fictional company worlds—procurement, SaaS support, and CRM/RevOps—have completed model-backed prospective selection and repeatability stages through the same candidate/runtime contracts.

## Exact evidence boundary

Demonstrated now:

- evaluation and safety architecture composes locally;
- same compiler code runs five role adapters;
- failures remain preserved;
- unseen-case fingerprints are sealed before release;
- candidate mutation after freeze is detected;
- authority stress passed a fixed deterministic campaign;
- model-backed selected specialists execute and verify multi-step workflows in three different fictional company worlds;
- response loss is reconciled without duplication;
- the compiler can activate a proved improvement or retain an existing specialist when an upgrade is not proved;
- selected specialists and alternatives survive a durable integrity-checked reload;
- current-runtime cross-role confirmation passed 3/3;
- exact paid-model spend through technical closeout is `$23.10699808`.

Not demonstrated:

- superiority over manual or incumbent workflows;
- real measured human-effort reduction;
- customer value, production reliability, security approval, or market demand;
- unbounded role or environment coverage.

## Closeout distinction

The bounded Level 1 technical mechanism is complete. The broader external evidence contract is not: the human-effort ledger has not yet been used in a prospective human-engineer study, and no customer or production environment has been evaluated.
